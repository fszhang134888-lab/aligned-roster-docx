# 对齐布局手册（制表位 + 中文字体度量 + 字体鉴定）

## 1. 为什么禁用空格补齐（血泪结论）

实测（Word 渲染 SimSun 14pt）：**U+3000 全角空格只占约半个字宽（~7.5pt，不是 14pt）**；ASCII 空格约 7pt；数字在宋体里可能全角（14pt）也可能半角。按"字符数"补空格在任何渲染器里都对不齐——实测 19 行名单有 4 行整体漂移 3~6pt，肉眼可见。

**制表位是唯一可靠方案**：`w:tabs` 定义绝对停靠点，`\t` 跳转，与内容宽度无关，Word/WPS 渲染一致。

### 1b. 例外：两字姓名中间的"显示空格"（与上条不冲突）

用户要求（项目硬性约定）：**两个汉字的姓名展示时中间插一个全角空格 U+3000**，`李明` → `李 明`。这与"禁用空格补列距"是两回事：

| | 补列距的空格（禁止） | 姓名内显示空格（要求） |
|---|---|---|
| 目的 | 用空格宽度把各列凑齐 | 纯显示美观，两字名拉开看着舒服 |
| 风险 | 空格宽度随字体/渲染器变 → 3~6pt 漂移 | 空格是姓名字符串的一部分，列起点仍由制表位决定，不漂移 |
| 做法 | ❌ 不用 | ✅ `scripts/name_format.py` 的 `display_name()` |

使用时三条注意：
1. **只改显示、不改键**：排序键、去重集合、正文首例姓名用原始无空格姓名；仅在拼名单行时 `display_name(n)`。否则 `李明` 和 `李 明` 被当成两个人，人数会虚增。
2. **宽度余量**：两字名加 U+3000 后约 35.5pt（U+3000 @14pt 宋体实测 ~7.5pt，非 14pt），仍 < 列距 62/70pt，不顶歪后续列；`LONG_NAME` 单独行判断按原始字数算。
3. **验证**：像素墨块检测会把 `李 明` 识别成两个墨块，可能污染"列签名聚类"。含该格式的文档改用 `verify_layout.py --stops <页面绝对停靠点列表>` 走停靠点驱动校验。停靠点换算：页面 x = 左边距 + 制表位（如左边距 62.4pt + 制表位 154/216/... → 216.4/278.4/...）。

## 2. 制表位布局计算（A4，单位 pt）

```
文本宽度 = 595.3 − 左边距 − 右边距
```

常用边距组合与文本宽度：

| 左边距 | 右边距 | 文本宽度 |
|---|---|---|
| 62.4 (2.2cm) | 62.4 | 470.5 |
| 79.4 (2.8cm) | 73.7 (2.6cm) | 442.2 |

**姓名名单行**（班级标签 + N 个姓名列）：

```
制表位[0] = 标签列宽   （必须 > 最长标签实际宽度 + 8pt 余量）
制表位[i] = 制表位[0] + i × 列距
列距 > 最长姓名宽度：3 字名 42pt@14pt；4 字名（如阿卜杜拉）56pt
```

实例（19 班 × 5 人，14pt 宋体，边距 2.2cm）：
- 最长标签「23计算机科学与技术2：」10 全角字 = 140pt → 标签列宽取 **154pt**
- 列距取 **62pt**（> 56pt，4 字名不重叠；3 字名间隙 20pt）
- 制表位：154 / 216 / 278 / 340 / 402；末列 4 字名右缘 402+56=458 < 470 ✓

**每行字数校验**：标签宽 + N×列距 ≤ 文本宽度，否则截断/折行。

## 3. 字号与纵向空间估算（判断一页放不放得下）

行高 ≈ 字号 × 1.2 × 行距倍数 + 段后间距。A4 可用高度 = 841.9 − 上边距 − 下边距。

经验：19 行名单 + 标题正文 + 落款，行距 1.5 + 段后 6pt 时约需 900pt → **两页**；行距 1.15 + 段后 1pt 时约 690pt → 可挤一页（边距 2.0cm）。**估算只用于预判，最终以 Word 转 PDF 实测页数为准**（Word 行高计算与估算常有几十 pt 出入）。

分页策略：
- 自然流式（去掉所有 page_break_before）：首页写满，余量去第二页——符合"第一页写满再第二页"；
- 均衡两页：在目标行设 `page_break_before`（注意坑位 #2，SDK 设了 true 后想取消必须删段重插）。

## 4. 中文字体规范速查（校园公文）

| 用途 | 字体 | 字号 |
|---|---|---|
| 标题（公假条/证明） | 宋体加粗（或黑体，以参照件为准） | 二号 22pt 居中 |
| 正文 | 宋体（参照件常为加粗） | 四号 14pt，首行缩进 2 字符 |
| 名单/落款 | 宋体 | 四号 14pt |
| 「具体名单：」等小标题 | 宋体 | 四号，顶格 |

公文标题国标是方正小标宋，学生文档实际多为宋体加粗——**以参照件鉴定结果为准**。

## 5. 扫描件字体鉴定（参照件是图片时）

无法提取字体名时用定量比对（PIL + numpy + scipy）：

1. pypdfium2 渲染参照件，crop 出目标文字（标题/正文各一块）；
2. 对每个候选字体（`C:\Windows\Fonts\simsun.ttc`、`simhei.ttf`、`STZHONGS.TTF`、`STSONG.TTF`、`simfang.ttf`、`simkai.ttf`）渲染同样文字，二分查找字号使墨高匹配；
3. 两个指标：
   - **笔画粗细**：距离变换（`scipy.ndimage.distance_transform_edt`）取 85 分位 ×2。参照 8.0 vs 候选 SimSun-reg 6.0 / STZhongsong 8.0 → 判粗细；
   - **字形 IoU**：候选 resize 到参照墨盒后算交并比。粗体标题 IoU 随加粗程度单调上升，取峰值。
4. 结论套路：正文宋体加粗（Word 伪粗，本机 simsunb.ttf 实为 SimSun-ExtB，不能直接用）；标题比正文明显粗 → 单独加粗。

注意：照片/扫描件会让笔画偏粗 10~20%，别追求绝对一致，看相对关系。

## 6. 本机可用字体（Windows + Office）

`simsun.ttc`（宋体，index 0=SimSun / 1=NSimSun）、`simhei.ttf`、`simfang.ttf`、`simkai.ttf`、`STZHONGS.TTF`（华文中宋）、`STSONG.TTF`（华文宋体）、`STKAITI.TTF`、`STXIHEI.TTF`。Word 对宋体加粗是伪粗合成，转 PDF 时原声保留。
